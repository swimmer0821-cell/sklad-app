# CLAUDE.md — Склад SUB PROFI (веб-приложение)

ПУБЛИЧНЫЙ репозиторий: всё, что здесь лежит, видит весь интернет. Секретов тут быть не должно.

## Что это
Мобильное приложение склада (PWA) ООО «SUB-PROFI»: приход, расход, выпуск, остатки, инвентаризация, сроки годности.
Пользуются сотрудники склада и руководитель, интерфейс на русском и узбекском (латиницей).
Данные хранятся в Google Таблице склада; приложение — только «окно» к ней.

## Где работает и как обновляется
- Сайт: GitHub Pages, ветка `main`. Изменения в `main` появляются на сайте сами через 1–2 минуты.
- Сервер: Google Apps Script внутри таблицы склада. Адрес — в `index.html`, `CFG.API_URL` (и отдельно в `cost.html`, константа `API`). Адрес не менять и не копировать в другие файлы.
- Код сервера в репозитории не работает: в `kod.html`, `kod2.html`, `kod3.html` лежат копии кода для вставки в Apps Script (кнопка «Скопировать»). После вставки: Начать развертывание -> Управление развертываниями -> Новая версия.
- ПРАВИЛО: при каждом изменении `index.html` поднимать ОБА номера: `APP_VER` в `index.html` (сейчас вида `2026-10-29-van`) и `CACHE` в `sw.js` (сейчас `sklad-app-v24`). Иначе телефоны останутся на старой версии.
- Приложение само проверяет `APP_VER` раз в 5 минут и при открытии; перезагружается, только если открыт главный экран и ничего не вводится.

## Карта файлов
- `index.html` — всё приложение (стили, экраны, переводы ru/uz, работа с сервером). ~1600 строк.
- `sw.js` — офлайн-кэш; сеть в приоритете, запросы к другим сайтам не трогает.
- `manifest.webmanifest`, `icons/` — установка на экран телефона.
- `cost.html` — отдельная страница себестоимости Laza (свой вход по ПИН владельца).
- `kod.html`, `kod2.html`, `kod3.html` — копии серверного кода: «Коридор» (выход продукции, загрузка сублиматора), «Себестоимость», «Уведомления».

## Что нельзя ломать
- Защита от двойной записи: функция `call(..., {write:true})` создаёт `rid`, и при повторе после обрыва связи отправляет ТОТ ЖЕ `rid`; сервер второй раз не запишет. Не убирать `rid` и не создавать новый при повторе.
- Показ партий по FEFO: первая в списке — с ближайшим сроком (метка «Ближайший срок»); выбор не первой партии даёт предупреждение «Не по сроку (FEFO)».
- Подсветка сроков: `CFG.EXPIRY_WARN_DAYS` (30 дней) и просроченные партии.
- Вход по ПИН-коду (экран `login`), токен хранится на телефоне; при ошибке авторизации `authFail` возвращает на вход. Не ослаблять.
- «Отменить последнюю запись» — только `CFG.UNDO_MIN` минут; инвентаризация и выгрузка из сублиматора не отменяются.
- Остатки считает таблица формулами; приложение их показывает, а не вводит. Исправление остатка — только через инвентаризацию.
- Цены везде без НДС 12%; в закупке способ оплаты «Карта» — без НДС. Валюта — сум.
- Тексты на двух языках: новый русский текст добавлять вместе с узбекским переводом (словарь и правила в `index.html`).
- При записи показывается окно «Не закрывайте приложение и не нажимайте повторно» — не убирать.

## Как проверять перед публикацией
1. Из папки репозитория: `python -m http.server 8000`, открыть `http://localhost:8000/` в браузере.
2. Ширина окна 390 px: нет прокрутки вбок, кнопки крупные, текст читается.
3. Без доступа к серверу экран входа и сообщение об ошибке должны открываться без «белого экрана»; консоль браузера без красных ошибок.
4. Проверить, что `APP_VER` и `CACHE` в `sw.js` подняты.
5. Рабочие записи на настоящем сервере не делать для проверки — только чтение, либо спросить владельца.
6. Для `kod*.html`: код правится в Apps Script вручную и проверяется там (кнопка «Сохранить» без ошибок).

## Как откатить
- Откат последнего изменения: `git revert <коммит>` и отправить в `main` (после нужно снова поднять `APP_VER` и версию кэша).
- Ветка-копия старого дизайна уже есть: `backup-before-redesign` (не удалять).
- Серверный код откатывается в Apps Script: Управление развертываниями -> предыдущая версия.

## Правила работы с владельцем
- Владелец не программист: объяснять простыми словами, без терминов; коротко, по шагам.
- Перед любыми изменениями, которые касаются рабочих данных склада, остатков, денег и ПИН-кодов, — сначала спросить.
- Не коммитить и не публиковать без явной просьбы.
- Секреты (токены, ПИН-коды, ключи) — только в свойствах скрипта Apps Script, никогда в коде, в `kod*.html` и в этом файле.
- Если данных нет — писать «уточнить» и задавать вопрос, числа не выдумывать.
